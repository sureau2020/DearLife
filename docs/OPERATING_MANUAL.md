## 增量更新协议

每次修改代码、配置、场景时，在该任务中执行：

1. 从文件路径及 diff 定位受影响模块，只读相关模块文档。新增路径按模块边界归属；新模块只初始化它自身。
2. 判定级别。公开契约变化时按索引“被依赖”和模块反向链接检查真实消费者，必要时定向读源码。
3. 只更新对应范围；同步提交基线、日期及工作区说明。最近改动摘要倒序保留最多 5 条。
4. 核对文件清单、依赖链接、事件签名、数据所有权和未实现项；汇报文件、级别、ADR。

| 级别 | 触发条件 | 更新范围 |
|---|---|---|
| L0 | 私有实现、内部重构 | 对应模块最近改动摘要；若行为描述已变化，同时修正描述 |
| L1 | 模块内新增/调整公开类或方法，无外部影响 | 对应模块 API、相关描述与摘要 |
| L2 | 接口、事件、跨模块字段或行为契约变化 | 模块相关章节和真实消费者的相关行；必要时 ADR |
| L3 | 新增/删除/改名模块、边界或职责变化 | 索引、相应模块文档、ADR |

索引只存布局、摘要、路径映射与链接。常规 L0–L2 不修改索引；新增 ADR 时允许仅追加 ADR 索引行，避免新记录无法发现。跨模块硬约束变化同时更新 conventions。

## 同步标记与防漂移

`最后同步：commit <hash>` 表示已核对的仓库 HEAD 基线，不要求它恰好是该模块最后一次修改的提交。未提交改动应明确写“包含工作区未提交改动”，不得宣称它们属于该 hash。

回答模块问题或开始维护前，对索引列出的所有归属路径检查：

- 用 `git diff <基线> HEAD -- <路径...>` 查基线以来已提交变更。
- 用 `git diff HEAD -- <路径...>` 查已暂存及未暂存的已跟踪变更。
- 用 `git ls-files --others --exclude-standard -- <路径...>` 查未跟踪文件。
- 可用 `git log -1 --format=%H -- <路径...>` 辅助定位最新提交，但不能因为它早于基线就判过期。

无差异可依文档回答；有差异先说明文档可能过期，并定向核对补全。基线无法解析或历史不可用时标记未核验，不假定最新。文档未覆盖时说明缺口，在任务所需范围内读取源码；用户若明确要求仅依文档，则遵守该限制。

## ADR

仅记录架构模式、模块拆合、跨模块约束变化及推翻旧决策；实现小改不写 ADR。初始化 ADR 是对已存在实现的现状记录，不杜撰历史讨论或决策者。

编号递增，记录状态、日期、背景、决策、备选方案、后果、模块链接。正文保留历史；替代时新增 ADR，并只更新旧记录状态/替代指针。新决策的授权仍取决于用户任务，文档不额外授权架构改造或发布。

## 模块文档格式

保留以下章节：目录/程序集、命名空间、最后同步、职责、公开 API、公开接口契约、依赖、被依赖、事件、数据所有权、文件清单、验证、最近改动摘要。不适用项明确写“无”；生成代码和资源也列入清单。

## 后续使用

- “改了某路径”：按路径执行 L0–L3 更新，无需重扫全项目。
- “更新最近 N 个提交”：先按 diff 分组，再分别增量同步。
- “基于文档回答”：先定位模块、检查漂移，回答标注 `docs/modules/<模块>.md §章节` 并给链接。
- 新模块只新增一份模块文档及索引；真实依赖边变化补相关反向引用。
- 全库重建须用户明确要求；里程碑审计按模块逐一核对，不自动重写。

文档修改本身不自动提交到 Git。需要提交时只纳入任务相关文件，避免混入其他工作区改动。
