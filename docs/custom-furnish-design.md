# 自定义装修素材设计

日期：2026-10-28。基线：`49fa54da6e0cec37f33577c8593db375d1a21015`；设计依据包含当前工作区。状态：规则已由用户确认，进入实现。

## 已确认的规则

- 导入宽、高均不超过 500 像素的图片；超限拒绝，不自动缩小。固定 16 像素对应一个房间格子。
- 十字锚点在图片内按像素移动，代表网格左下角；仅向右、向上生成格子，不足一格向上取整。锚点左、下侧的图像仍完整显示。
- 家具：白格不阻挡，红格阻挡；点击切换，允许全白。装饰：只有锚点，不编辑碰撞。地板：整张房间背景，白格可走、红格不可走，至少保留一个可走格。
- 保存素材只加入本地素材库；使用背景仍走原有确认换房间流程，清除当前摆放实例。

## 界面与状态

三个分类均提供“导入”入口，共用 `CustomFurnishEditor` prefab。分类由入口确定。包含素材名称、选择图片、全图操作区、尺寸和格子说明、修改锚点开关、保存、取消。

初始不能保存。选择图片后完整等比显示，默认锚点为图片左下角、网格全白。修改锚点模式允许点击或拖动锚点，网格模式允许切换白/红格。锚点变化清除红格，操作区始终提示此规则。装饰隐藏格子。屏蔽背后的房间点击。

选图取消不丢失原草稿；面板关闭/销毁后丢弃迟到的相册回调。保存中禁用重复提交，失败保留草稿；取消销毁临时 Texture2D。保存后的运行时 Sprite/Texture 由素材库持有，游戏管理器销毁时释放。

## 数据与现有系统接入

- `CustomFurnishData`：版本、稳定 ID、名称、类别、图片尺寸、锚点像素坐标、红格坐标。用普通字段 DTO 持久化，避免序列化 Unity 对象和 Vector 的派生属性。
- `CustomFurnishLibrary`：存于 `persistentDataPath/CustomFurnish/<id>/`，含 `image.png` 和 `data.json`。先写临时目录，两文件完成后再改名发布。只在磁盘写入成功后注册素材。启动逐项验证，坏文件隔离跳过，其他素材仍可用。
- `FurnitureDatabase` 拥有自定义库，将家具/装饰投影为现有数据；使用锚点作为 Sprite pivot，PPU=16，现有实例放置与移动坐标不变。旧家具/装饰 JSON 路径保留兼容。
- 家具红格复用现有占用/寻路；白格不写阻挡。全白家具保留锚点选中入口和绿色提示，修复空占用集合的排序极值。
- 自定义背景在 RoomView 单独绘制完整图片，GridMap 只生成锚点右上方的逻辑格子。地图存档增添可选背景 ID，旧存档缺省为空；恢复时从本地库找图片。内置房间继续原有 Tilemap 流程。
- 换房间或家具改变行走区域时，角色废弃旧路径；当前格不可走时迁移到可走格，避免停在新背景外或继续穿过新家具。
